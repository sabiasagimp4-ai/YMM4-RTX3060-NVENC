# YMM4 RTX 3060 NVENC 出力

> **開発途中のcheckpointです。** YMM4 4.56.1.0 の DLL を使ったビルドと、GPU（WARP）を使う自動テストの一部は GitHub Actions の Windows 環境で実行しています（新しい YMM4 の版も自動で検査します）。同じ環境で実際の YMM4 4.56.1.0 を起動し、先読み・キャッシュの帯・シーク後の表示を画面写真で確認しましたが、この PC（RTX 3060、4.55.1.1）の YMM4 での動作と NVENC 出力は未確認です。完了を確認できない動画を含むフレームは保存しません。既存 `dist` は最新ソースに対応しません。続きは [Claude引継ぎ資料](CLAUDE_HANDOFF.md) を参照してください。

RTX 3060 を搭載したこの PC 向けの、ゆっくりMovieMaker4 動画出力・描画キャッシュプラグインです。YMM4 の GPU フレームを Direct3D 11 経由で NVENC に渡し、MP4（H.264 または HEVC、AAC 音声）を出力します。対応版では合成済みフレームを RAM・ディスクへ保存し、変更のないフレームを再利用します。

MIT ライセンスの [YMM4_NVEncPlugin](https://github.com/tarutaru247/YMM4_NVEncPlugin) を基にしています。[Radeon AMF 実装](https://github.com/disnana/YMM4_AMF_Plugin) と [GPU 出力の解析記事](https://qiita.com/harupython/items/f03cd6f04375115f82f9) を出力経路の参考にし、指定された [高速化の記事](https://qiita.com/harupython/items/4be768e58cba3a2921b3) を実行時フック・更新省略の調査に使いました。Radeon 用 AMF と libvips は組み込んでいません。

## この PC での対象

- Windows 11、YMM4 Lite v4.55.1.1（.NET 10）、i7-13700KF、RTX 3060 12 GiB、NVIDIA ドライバー 610.62。
- H.264 と HEVC の NVENC 出力。RTX 3060 は AV1 エンコードに対応しないため、AV1 は設定から除外しています。
- 既定値は H.264、標準品質、解像度と fps に応じた可変ビットレートです。品質やビットレートを変えると画質と速度も変わります。
- GPU フレームは CPU に読み戻さず、所有 D3D11 テクスチャへコピーして NVENC に入力します。入力テクスチャの寿命を越えて参照しない設計です。
- 上記は NVENC 入力経路の説明です。描画キャッシュの画素保存には CPU readback があり、全経路が readback 不要という意味ではありません。

## ビルドとインストール

この PC には .NET 10 SDK、Visual Studio 2022 の C++ ツール、Windows SDK 10.0.26100.0 が必要です。YMM4 の配置を変えた場合は `-Ymm4DirPath` を指定してください。

```powershell
.\build.ps1 -Smoke
```

成功すると `dist/YMM4-RTX3060-NVENC.ymme` と SHA-256 ファイルができます。`-Smoke` はこの GPU で H.264/HEVC と AAC の1秒の MP4 を実際に生成・デコードします（`ffmpeg` と `ffprobe` が PATH に必要）。通常のビルドでは `-Smoke` を省けます。ビルドは YMM4 のプラグインフォルダーへ自動配置しません。

1. YMM4 の作業中のプロジェクトを保存して終了します。
2. `.ymme` を開いて、インストーラーで普段使う YMM4 を選びます。
3. YMM4 を起動し、動画出力の「RTX 3060 NVENC 出力」を選びます。まず短い区間を新しいファイル名で出力し、映像・音声・同期を確認してください。

偶数幅・偶数高さが必要です。失敗時は完成ファイルを置き換えず、出力先に `.partial` ファイルを残します。デバッグログを有効にした場合は、同じ出力先に `.partial.nvenc_log.txt` が残ります。不要になった失敗ファイルは内容を確認してから削除してください。

## キャッシュと停止対策の範囲

YMM4 Lite の内部処理に Harmony の実行時フックで接続します。本体ファイルは変更しません。YMM4 の版ごとの扱いは次のとおりです。

- **動画出力（取消保護つき）**: どの版でも、YMM4 の出力処理の形（メソッドやフィールドの名前と型）が想定どおりなら使えます。取消や途中の失敗で予定のフレーム数に届かなかった出力は完成ファイルを置き換えないので、本体の中身が変わっても既存のファイルを壊しません。形が変わった版では出力を開始しません。
- **自動キャッシュ**: 中身を読んで確認した版（4.56.1.0。4.55.1.1 は一部の機能のみ）では、配置・MVID・SHA-256 の一致を確かめて使います。それ以外の版では、起動時に本体の DLL を読み、キャッシュが前提にしている本体のコード（描画処理、フレームに描くアイテムの選び方、ほかのシーンを読むコード、描画中に読まれる設定、素材ファイルの列挙、動画の読み込み部分など）が 4.56.1.0 と同じかを機能ごとに照合し、同じだった機能だけを使います（照合は版が変わった最初の起動だけ数秒かかり、結果は保存されます）。照合は 4.56.1.0 の確認と同じ観点を機械的に比べるもので、それ以上の保証ではありません。違いがあった機能は通常描画になり、ツールの「描画キャッシュ」に理由が表示されます。
- **新しい版の自動確認**: GitHub Actions の `ymm4-watch` が毎日 YMM4 の更新サーバーを確認し、新しい版が出ていれば取得して、上の照合・プラグインのビルド・Windows での検査を行い、結果を issue にします（このワークフローは main ブランチに取り込まれてから動きます）。

使う機能は次の3つを別々に切り替えられます（ツール「描画キャッシュ」と、YMM4 の設定の「その他 > RTX 3060 NVENC・描画キャッシュ」。同じ設定です）。

- **プレビューで描画キャッシュを使う**: YMM4 標準のプレビュー（再生・一時停止・シーク）のまま、保存したフレームを再利用します。アイドル時の先読みとキャッシュの帯もこれに含まれます。
- **動画出力で描画キャッシュを使う**: 動画出力の描画（YMM4 標準の出力形式でも NVENC 出力でも）でフレームを保存・再利用します。
- **RTX 3060 NVENC 出力を使う**: 出力形式「RTX 3060 NVENC 出力」。切ると、この形式を選んでも出力せずに理由を表示します（YMM4 の一覧には残ります）。起動時に切れていれば、出力用のフックも入れません（後で入れたときはその場で入れます）。

既定は NVENC 出力のみ有効です。以前の版の「描画キャッシュを有効にする」の設定は、プレビューと動画出力の両方に引き継ぎます。ツールの「描画キャッシュ」では状況確認と保存内容の消去もできます。RAM 上限は256 MiB、ディスク上限は4 GiB、GPU 予約上限は384 MiB、1フレーム上限は128 MiBです。画素は非可逆圧縮をせず保存します。保存データの破損や容量上限は通常描画への切り替えとして処理します。動画素材のデコードが要求時刻まで完了したと確認できないフレーム（読み込みの timeout など）は保存しません。GPU・ドライバー・プラグインのビルドが変わると、以前に保存した画素は使いません。編集操作中（最後の変更から 250 ms 以内）は通常描画を使い、編集が落ち着いてから再びキャッシュを使います。プレビューは再生中・一時停止中（シークを含む）ともキャッシュを使い、そのとき YMM4 が描画したフレームも保存します（GPU からの読み戻しは次の描画のときに仕上げ、描画スレッドが GPU を待たないようにしています）。ディスクにだけあるフレームは、再生中は再生位置の約0.5秒先まで先に読み込み、一時停止中は最大50 ms 読み込みを待ってから表示します（読み込みは書き込みより優先）。`ShowOnlyPreviewEffect` を使うプロジェクトでは、再生用と一時停止用を分けて扱います。YMM4 がアイテムの選択枠・操作点を必要とするフレームでは、同じ編集状態で一度通常描画したときの選択枠を復元します。選択枠がまだないフレームは、一時停止中でマウスがプレビューの外にあるときだけキャッシュから即時表示し、その位置で約0.1秒止まると（マウスをプレビューに乗せたときは直ちに）YMM4 が通常描画して選択枠を表示します。マウスがプレビュー上にあるときや再生中は、選択枠がまだなければ通常描画します。メッシュ変形を含むプロジェクトと、選択枠の扱いを確認していない YMM4 の版（4.56.1.0 と、その部分のコードが 4.56.1.0 と同じ版以外）では、選択枠が必要なフレームは従来どおり通常描画します。このプラグインが中身を確認していないコード（ユーザーが追加したプラグインのエフェクト・図形・アイテム・トランジション・ブラシ、YMM4 同梱の Community プラグインのうち確認していないもの）を使うアイテムは、そのアイテムが映るフレームだけを通常描画にします。YMM4 同梱の Community プラグインは、4.56.1.0 のコードを読んで、自分のアイテムだけを設定と時刻から描くと確認したもの（エフェクト 60 種・図形 2 種・ブラシ 2 種・トランジション 4 種）を自動でキャッシュ対象にしています（前のフレームを使う MotionBlur・AfterImage、音声を読む AudioVolume、外部バイナリを読む OpenFx などは対象外）。ユーザーが追加したプラグインは、設定「外部プラグインを使うフレームもキャッシュする」でチェックしたものだけ、YMM4 のコードと同じようにアイテム単位でキャッシュします（既定はなし。プラグインが設定と時刻だけで描くことが前提で、そうでないプラグインでは古い絵や違う絵が出ることがあります。プラグインの更新で作り直します）。ほかのタイムライン（シーン）にあればシーンアイテムが映るフレームだけ、キャラクターの字幕エフェクトにあればそのキャラクターのアイテムだけ、音声エフェクトにあれば音声を読むフレーム（シーンアイテム・音声波形）だけです。音声合成プラグインと立ち絵プラグインのパラメーターは、キャッシュするフレームの描画に使われないため影響しません。プロジェクト全体の設定（タイムラインの映像設定など）に外部の型がある場合だけ、全体を通常描画にします。カスタム読み込みプラグインが有効なときは、素材ファイルを使うアイテム（とキャラクター）のフレームだけを通常描画にします（YMM4 に同梱され、YMM4 のフォルダーから読み込まれる読み込みプラグインは組み込みとして扱います）。立ち絵は口パクが非同期に計算されるため、立ち絵が映るフレームだけを通常描画にします。AE の全機能との互換性は保証しません。

フォントは YMM4 の描画と同じ手順で解決します。フォント名を YMM4 のフォント設定（システムフォントとカスタムフォント）で探し、見つからなければ YMM4 と同じく Arial として扱い、得られたファミリー・太さ・スタイル・幅を DirectWrite のシステムフォントから探します。この対応はキーに含まれ（フォント設定を変えるとそのフォントのフレームだけ作り直し）、ファミリーのフォントファイルは素材として内容を確認します。DirectWrite にないファミリーのフォントを使うアイテムだけ、映るフレームを通常描画にします。文字装飾や制御タグ（`<@フォント名>`）で指定したフォントも、フォント設定にあれば同じように解決します（無い名前は YMM4 と同じくアイテムのフォントで描かれます）。文字がフォントにないときに DirectWrite が使う代替フォントは追跡しません。テキストと字幕は、YMM4 が描画前にユーザー辞書の「*」置換（アスタリスク置換）で書き換えるため、その設定もテキスト・ボイスアイテムのキーに含めます（読めない場合はそれらのアイテムだけ通常描画）。

キャッシュはフレーム単位です。各フレームの保存キーは、プロジェクト全体の設定（描画に使われる YMM4 の設定: 拡大縮小の補間、動画の読み込み方式、音声のアップサンプリング、拡張子ごとのファイルの種類を含む）と、そのフレームに重なるアイテム（トランジションはその直前のフレームのアイテムも）と、それらが使う素材ファイルの内容から作ります。アイテムを編集しても、そのアイテムが映るフレームだけが作り直しになり、ほかのフレームのキャッシュは残ります。素材ファイルの確認もそのフレームで使うファイルだけを行い、背景での内容確認は要求されたフレームのファイルから先に行って、確認できた分から使います。時刻は要求された時刻そのもの（100 ns 単位）をキーにするので、フレームの境界のすぐ手前の時刻が別の動画サンプルを指す場合も混同しません。シーンアイテムや音声波形（オーディオスペクトラム）図形が映るフレームは、従来どおりプロジェクト全体に依存します。素材ファイルは最大4096個まで背景で内容を確認し、確認できないファイルはそれを使うフレームだけを通常描画にします。YMM4 の起動中に素材ファイルを同じ名前で上書きした場合、そのファイルを使うフレームは YMM4 を再起動するまで通常描画にします（YMM4 は読み込み済みの内容を、アイテムがフレームから外れて読み直すまで使い続けるため、古い内容と新しい内容のどちらも表示し得ます）。キャッシュを無効にしていた間の上書きは検出できません。YMM4 の「ランダム移動」や一部のエフェクト（ランダム移動・回転・拡大・傾き・透明度、ランダム複製、クラッシュ、ランダムライン、ノイズ）は、YMM4 の起動ごと・プロジェクトを開くごとに違う乱数で描かれます。これらを使うアイテムのフレームは、そのとき開いているプロジェクトの間だけキャッシュを使い、先読みはしません（以前は別の起動時の絵を混ぜて表示し得ました）。文字を「ランダム」の順で表示・消去するテキストと字幕は通常描画にします。MIDI ファイルを使うプロジェクトでは、音声を読むフレーム（音声波形図形・シーンアイテム）を通常描画にします（YMM4 同梱の MIDI 読み込みは独自の設定と SoundFont で音を作り、それらはキーに含めていないため）。

キャッシュ状況は After Effects のように色の帯で表示します。緑はRAM（すぐ再生できる）、青はディスクに保存されたフレームです。タイムラインの目盛り（ルーラー）の下端に3ピクセルの帯を重ね（4.56.1.0 と、ルーラー部分のコードが同じ版のみ）、ツールの「描画キャッシュ」にはタイムライン全体の帯を表示します。帯はプレビューの現在の表示倍率・位置で保存されたフレームを示します。プレビューが止まっている間（最後にプレビューが描画されてから2分以内）は、再生位置から10秒先までを先読みします（保存済みのフレームは描き直しません）。ツールの「描画キャッシュ」には、再利用の内訳（同じ画像・RAM・ディスク）、新規描画、対象外、プレビュー保存数と描画スレッドでの時間、ディスクの読み書きを表示します。

ディスクの初期化・読み書き・整合性検査は専用スレッドで行います。ディスクにだけ残っているフレームは最初の要求時に通常描画し、読み込み完了後に再利用します。保存キューは128件・128 MiBが上限で、満杯時は追加のディスク保存を省略します。消去では保存世代を永続化し、消せなかった旧ファイルが次回起動で復活することを防ぎます。別プロセスが保存領域を使用中など、消去を永続化できない場合はツールにエラーを表示します。

現在の出力経路では次を修正しています。

- 現行YMM4の `IVideoFileWriter3.IsGpuFrameSupported` でGPU入力対応を明示。
- 最初の映像より前に届く音声は一時ファイルへ退避し、64 KiBずつ再生。成功・失敗どちらでも一時ファイルを閉じて削除。48 kHzステレオでは一時ディスクを約1.3 GiB/時使用します。
- 非同期NVENC入力は、出力完了までスロットごとの所有テクスチャとマッピングを維持。入力デバイス・寸法・形式の不一致は出力失敗として扱います。
- NVENC 呼び出しを専用 MTA スレッドへ集約。終了・取消・失敗時は EOS と未完了入力の回収を済ませてから解放し、予定フレーム数未達や取消時は完成ファイルを公開しません。
- 書き込みキューは64 MiB・256サンプルが上限で、満杯時は空きを待ちます。30秒進まなければ失敗を返し、書き込み失敗時には待機を解除します。これはOSやドライバー内の停止を解消する保証ではありません。
- AAC入力の内部PCM蓄積を最大1024フレームに縮小。NaNは無音、無限大は振幅上限へ変換。AACは44.1/48 kHz、モノラル/ステレオを対象とします。
- HEVCの有効なNALを保持し、MP4の時刻情報を正しい単位・64ビット長で保存。fpsによる丸めの累積と長時間出力の32ビット桁あふれを回避。

MP4のサンプル索引は出力時間に比例してRAMを使用します。ディスク不足、GPUデバイス喪失、OSのI/O停止、ドライバー内部の停止、YMM4本体の不具合まで含む「全バグ・全停止の解消」は保証しません。

## 検証範囲

この PC のドライバー上で H.264/HEVC の NVENC と AAC の 30 フレーム MP4 をオフラインで生成し、`ffprobe` と全フレームデコードで確認しました。YMM4 の旧形式フレームが届いた場合や映像なしの音声が届いた場合も、無言で成功扱いせず失敗することを確認しました。YMM4 の実プロジェクトでの速度比較、長時間出力、キャンセル時の動作は未検証です。描画が主なボトルネックの場合、NVENC を使っても出力速度が大きく変わらないことがあります。

`-Smoke` はキュー満杯時の失敗通知、未初期化ハンドル、HEVC NAL、37 fpsの時刻情報、30時間相当のMP4ヘッダー、取消・失敗時の入力回収も検査します。32 MiBの先行音声に対する管理側の全スレッド合計の追加割り当ては12,896バイトでした。GPUフレームとの結合後に音声の長さと振幅を検査し、失敗した出力が既存ファイルを置き換えないことも確認します。30時間の実レンダリングを行った結果ではありません。

速度測定は `./tests/benchmark.ps1 -Runs 3` を使用します。1920×1080・300フレームの合成素材で、標準H.264の中央値は修正前0.972544秒、修正後0.965070秒、標準HEVC非同期は0.448047秒から0.444657秒でした。1%未満の差なので、このケースの高速化とは断定しません。HEVC非同期と同期の300フレームは、デコード後の全フレームハッシュが一致しました。これらはエンコード経路の計測で、編集プレビューや実プロジェクト全体の速度を表しません。

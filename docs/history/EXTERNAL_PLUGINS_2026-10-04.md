# 外部プラグインを自動でキャッシュの対象にする方法（設計案と実験、2026-10-04）

## 1. 今の扱い

- 外部プラグインの型（エフェクト・図形・トランジション・ブラシ・アイテム）が映る区間は、通常描画（YMM4 がそのまま描く）。ほかの区間は対象のまま。
- 設定で「信頼」したアセンブリは、名前と MVID をキーに入れて対象にする。中で何を読むかは確かめない（利用者の判断）。
- 乱数のうち、YMM4 の「ランダム移動」（`Animation`）は、外部プラグインのパラメーターの中にあっても追跡している。プラグインが自分で持つ乱数は追跡していない。
- Community（同梱プラグイン）は、コードを読んで約 70 種を対象にした（[KnownCode.cs](../../NVEncVideoWriterPlugin/KnownCode.cs)）。

外部プラグインを対象にできない理由は、「同じ設定・同じ時刻なら同じ絵になる」ことを確かめる手段がないこと。Community で手で確かめた項目は次のとおり。

| 隠れた入力 | 例（Community） | 起きること |
| --- | --- | --- |
| 前に描いたフレーム | 残像、モーションブラー | 描く順番で絵が変わる |
| オブジェクトの同一性を種にした乱数 | CameraShake、グリッチノイズ | 起動し直す・複製すると別の乱数になる |
| 種のない乱数、時計 | （外部プラグインで起こり得る） | 描くたびに変わる |
| 報告しないファイル | LUT、グラデーションマップ | ファイルを変えても検出できない |
| ほかのアイテム・シーン・音声 | グループ制御、シーンのブラシ、音量で動かすエフェクト | そのアイテムの外の変化を検出できない |
| ネイティブのプログラム | OpenFX、VST3 | 中身を確かめられない |

## 2. 方法（3 段）

手で読む代わりに、次の 2 つを組み合わせて自動で判定する。どちらも YMM4 の中で、利用者の操作を邪魔しない時に行う。

### 2.1 コードの自動検査（静的）

プラグインの DLL の中間言語（IL）を読み、描画の処理から呼ぶメソッドをたどって、隠れた入力に当たる呼び出しを探す。

| 見つけたもの | 判定 |
| --- | --- |
| 時計（`DateTime.Now`、`Stopwatch`、`Environment.TickCount`）、種のない乱数（`new Random()`、`Random.Shared`、`Guid.NewGuid`） | 対象外 |
| ファイル・ネットワーク・ネイティブ（`File`、`FileStream`、`HttpClient`、`DllImport`、`Process`） | 対象外（ファイルは 2.4 で緩める） |
| YMM4 の API のうち、ほかのアイテム・シーン・音声を読むもの（`EffectDescription.GroupCount`／`GroupIndex`、`ISceneInfo.TryCreateVideoSource`／`TryCreateAudioSource`、`TimelineSourceDescription.Scenes`） | 対象外 |
| 同一性のハッシュ（`object.GetHashCode`、`RuntimeHelpers.GetHashCode`） | 「同一性の乱数」の候補（2.3） |
| 何も見つからない | 試し描きへ |

静的な検査だけでは「前に描いたフレームを使う」処理（残像・モーションブラー）を見分けられない（実験で確認、3 章）。これは試し描きで見つける。

### 2.2 試し描き（動的）

アイテムごとに、実際のパラメーターで数フレームを描き、条件を変えて描き直して画素を比べる。

| 比べる描き方 | 違えば |
| --- | --- |
| 同じ描画器で、別の順番で描き直す（29→3→17 など） | 前のフレームに依存（対象外） |
| 少し時間をおいて同じフレームを描き直す | 時計・種のない乱数（対象外） |
| 新しく作った描画器で描く | 描画器ごとの状態（対象外） |
| プロジェクトを複製して描く | 同一性の乱数（2.3） |

全部一致したら、そのアイテムはそのパラメーターの間、対象にする。キーにはプラグインの MVID を入れる（更新すると最初からやり直し）。パラメーターを変えたら、そのアイテムだけ試し描きし直す。試し描きが済むまでは、今と同じく通常描画。

### 2.3 判定と扱い

| 静的 | 試し描き | 扱い |
| --- | --- | --- |
| 対象外の呼び出しあり | （行わない） | 通常描画。ツールに理由（例:「時計を読む」）を出す |
| なし | 全部一致 | 対象（起動し直しても使えるキー） |
| なし／同一性のハッシュ | 複製だけ違う | 同一性の乱数。今のランダム移動と同じく、その起動中のそのアイテムに限ってキーにし、停止中の先読みは実物のプロジェクトで描く |
| 同一性のハッシュ | 全部一致（その設定では乱数を使わない） | 安全側で同一性の乱数として扱う |
| どれでも | 順番・時間・新しい描画器で違う | 通常描画 |

### 2.4 その先（必要になったら）

- **ファイルを読むプラグイン**: パラメーターの文字列のうち、実在するローカルファイルを指すものを指紋にかけてキーに入れる。試し描きの間に開いたファイルを記録し、それ以外を開いていたら対象外。
- **プラグイン自身の設定**（`SettingsBase` を継承した設定）: 描画に効く可能性があるので、そのプラグインの設定の内容をキーに入れる。
- **乱数を固定してよい（利用者の選択）**: 描くたびに変わる乱数のプラグインは、YMM4 自身も描くたびに違う絵を出す。利用者が選んだプラグインに限り、最初に描いた絵を使い回す（YMM4 と同じ絵になる保証はなくなる）。

## 3. 実験: Community の手動監査を答えにして確かめた

Community（4.56.1.0、MVID `ac765de8`）を外部プラグインとみなし、2.1 と 2.2 を CI の実物の YMM4 で動かした。答え合わせには手で読んだ結果（対象・同一性の乱数・対象外の理由）を使った。試し描きは 192×108、直線移動する図形に既定のパラメーターのエフェクトを 1 つ掛けた。

### 3.1 静的な検査（Community の全名前空間）

| 手動の判定 | 数 | 静的な検査の結果 |
| --- | --- | --- |
| 対象（読んで確かめた） | 67 | 65 は何も見つからない。2 つ（PDF ページ、反射と押し出し）はファイルの読み込みを見つけた。どちらも YMM4 に報告するファイルなので、2.4 のファイルの扱いで区別できる |
| 同一性の乱数 | 4 | 4 つとも同一性のハッシュを見つけた。対象の 67 には 1 つもない |
| 対象外: ネイティブ（OpenFX） | 4 | 4 つともネイティブを見つけた |
| 対象外: ファイル（LUT、グラデーションマップ） | 2 | 2 つともファイルを見つけた |
| 対象外: 音声（AudioVolume） | 1 | 音声の読み込み（`ISceneInfo.TryCreateAudioSource`）を見つけた |
| 対象外: ほかのアイテム・シーン | 5 | 分類としては何も見つからないが、ほかの対象が使わない YMM4 の API（グループの番号・数、シーンの描画）を使う。これを禁止の一覧に入れれば区別できる |
| 対象外: 前のフレーム（残像、モーションブラー） | 2 | **見つけられない**（試し描きで見つかる） |
| 未読（手動では読み切っていない 8 種） | 8 | 3 つ（DirectionalColorKey、FillSameground、FillSametype）は何も見つからない。ほかは同一性のハッシュ、`Guid.NewGuid`、スレッド、ファイル |

余計に見つけたもののほとんどは、リソースの遅延読み込みとデリゲートのキャッシュ（無害な静的フィールドの書き込み）だった。これらは規則で除外した。また、この実験は名前空間のメソッドを全部たどったので、編集画面（UI）のコードも検査に入った。Puppet Deformation・Vector Field Warp で見つけた `Guid.NewGuid` やスレッドは試し描きでは影響がなく、UI 側のものと思われる。製品では、描画の処理（`CreateVideoEffect` が返す処理の `Update` など）から呼ぶものだけをたどる。

### 3.2 試し描き（Community のビデオエフェクト 88 種）

| 結果 | 数 | 内訳 |
| --- | --- | --- |
| 全部一致 | 36 | 33 は手動でも対象。2 つ（Puppet Deformation、Vector Field Warp）は手動では未読。1 つは WaveClipping（下記） |
| 既定の設定では何もしない（図形だけの絵と同じ） | 43 | 判定できない（実際の利用ではその人の設定で試すので問題にならない）。グループ・音声・ファイルを使うものは、この実験では材料がないので何もしない |
| 複製だけ違う（同一性の乱数） | 6 | CameraShake、グリッチノイズ 2 種（手動と一致）、パーティクル 3 種（手動では未読。静的にも同一性のハッシュ） |
| 順番・時間・新しい描画器で違う | 3 | 残像、モーションブラー（手動と一致）、**CircularBlur（手動では対象）** |

WaveClipping（手動では同一性の乱数）は、既定の設定では全部一致した（その設定では乱数を使わない）。静的な検査は同一性のハッシュを見つけるので、2.3 の規則で安全側に扱える。

### 3.3 CircularBlur

手動で読んで対象にしていたが、試し描きで前のフレームへの依存が見つかった。フレーム 17 を描いた絵を比べた結果（192×108、82,976 バイト）:

| 描き方 | 動く図形 | 止まった図形 |
| --- | --- | --- |
| 16 の次に描く（順に再生）／新しい描画器で最初に描く | 基準 | 一致 |
| 3 の次に描く（飛んで描く）、複製で 3 の次に描く | 1,200 バイト（約 300 画素）が最大 30／255 違う | 一致 |
| 直前に 17 自身を描いてから描く | 12 バイトが 1／255 違う | 一致 |

動く図形の縁だけが、直前に描いたフレームによって変わる。残像・モーションブラーと同じ種類の依存で、量が小さい。これまでの版ではキャッシュの対象だったため、シークで飛んだ時に保存した絵が、順に再生した時の絵と縁でわずかに違い得た。**今回、対象から外した**（映る区間は通常描画）。CacheChecks に、CircularBlur のフレームがキー化されないことの検査を加えた。

同じ条件で、残像は 15,000 バイトが最大 193、モーションブラーは新しい描画器で 1,200 バイトが最大 64 違った。どちらも止まった図形では一致した。図形が動かないと前のフレームへの依存は表に出ないので、試し描きは動くアイテムで行う必要がある（実際の利用ではそのアイテムの動きのまま試す）。

### 3.4 まとめ

- 静的な検査と試し描きを組み合わせると、Community の手動の判定のうち、同一性の乱数 4 種と対象外の理由（ネイティブ・ファイル・音声・ほかのアイテム・前のフレーム）を、この実験の範囲ですべて再現できた。対象とした判定で食い違ったのは CircularBlur だけで、調べると手動の判定の誤りだった。
- 手動で読んで対象にした CircularBlur が、試し描きで前のフレームに依存すると分かった（縁だけ、最大 30／255）。コードを読むだけでは見落とすことを、試し描きは見つけられる。
- 逆に、既定の設定で何もしないエフェクト（43 種）は、この実験では確かめられていない。手動で対象にしたもののうち 27 種がこれに当たる。設定を変えた試し描きで、手動の判定を確かめ直す価値がある。

## 4. 自動でも判定できないもの

- **試していない条件で初めて現れる隠れた入力**: 例えば、特定のパラメーターの時だけ別のコードを通る、まれにしか変わらない。静的な検査で呼び出しを見つけられれば防げるが、YMM4 の API や他の DLL の中で起きるものは見落とし得る。
- **リフレクションや動的なコード**: 静的にたどれない。対象外にする。
- **非同期の読み込み**（別スレッドで準備し、終わるまで仮の絵を描く）: 試し描きの時は準備が終わっていて一致しても、本番では未完成の絵を保存し得る。スレッドを使うプラグインは、完成を確かめる仕組みがない限り対象外にする（立ち絵の口パクと同じ問題）。
- **動かないと表に出ない依存**: 前のフレームへの依存は、アイテムが動く時だけ絵に出る（CircularBlur、残像、モーションブラー）。止まっているアイテムで試し描きして一致しても、後でキーフレームを足して動かせば試し直しになる（パラメーターが変わるため）。

## 5. 進め方

1. **すぐできること**: 使っている外部プラグインの名前を教えてもらえれば、Community と同じく 1 つずつ読み、MVID 付きで対象の一覧に入れる。自動の仕組みより早く、確実。
2. **自動の検査**: 2.1（静的）と 2.2（試し描き）を製品に入れる。試し描きは停止中の先読みの仕組み（実物のプロジェクトを描く描画器・複製を描く描画器）を使う。ツールに、プラグインごとの判定と理由を出す。
3. 2.4（ファイル、プラグインの設定、乱数の固定）は、実際に使うプラグインで必要になったものから。

実験のコード（一時的なもの、今は削除）は `tests/HostCacheProbe/PluginAuditProbe.cs`（コミット `124a678`〜`4dee16c`）。CI の run: 静的な検査 [37178809870](https://github.com/sabiasagimp4-ai/YMM4-RTX3060-NVENC/actions/runs/37178809870)（試し描きは 1 種目の後に止まり、時間切れ。静的な検査の出力は完全）、試し描き 88 種 [37181299282](https://github.com/sabiasagimp4-ai/YMM4-RTX3060-NVENC/actions/runs/37181299282)、CircularBlur の詳細 [37181828194](https://github.com/sabiasagimp4-ai/YMM4-RTX3060-NVENC/actions/runs/37181828194)。試し描きでは、Community のシェーダーが WPF の `pack://` の URI で読み込まれるため、検査のプロセスで URI の形式を登録した（YMM4 の中では不要）。

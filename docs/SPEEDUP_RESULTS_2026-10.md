# 高速化の結果（2026-10）

起点は `main` `8aa03b2` と指定の計画ブランチ `1cd7b21`。レビューの7件を更新した PR #5 の上に、項目ごとの draft PR を積み重ねる。main への push、merge、release は行わない。

## 項目1：ボイスの埋め込みデータをハッシュにする（PR #6、検証中）

ホストのJSON設定をコピーし、4 KiB以上の `byte[]` をSHA-256で記述する。先読みの複製はJSONの同じ位置に結び付けた元の配列の内容を検証して復元する。監査した4.56.1.0の標準ボイス以外の配列は複写し、書き換えをライブへ伝えない。JSONに入らない生成済み音声ファイルのパスも渡し、通知のないパス変更で古いcaptureが採用されないことを検査する。記述の弱参照にデータの証拠を結び付け、古い記述の保持が終われば解放できる。

計画との差：配列ごとのプロセス全体のハッシュ記憶は使わない。`VoiceCache` はホストの生成・読込では差し替えられるが、公開された `byte[]` と他の埋め込み配列すべての不変性までは保証できない。1記述内の重複計算だけを省き、次の記述で再確認する。CIで配列を直接1 byte変える検査を追加した。

計測の起点は計測だけの `c6bbe36`。3秒、mono PCM16、24 kHz のBrotli WAVを持つ50・200・500ボイスを各2回測る。50ボイスで、編集から250 msの落ち着く時間を含むキー回復も測る。修正前と後は、同じWindows jobで別processとして測る。WARPであり、RTX 3060の値ではない。

計測データの準備では、キャラクターと音声エンジンがないボイスを作ったため、ホストの `VoiceFactory.GetVoicePlugin` が例外になった（run 37186587776、37186904222、37187142127、37187344932）。試験の再実行ではなく、診断を加えて原因を確認した。ホスト標準の「なし」音声エンジンを明示した試験へ修正し、一時的な診断は取り除いた。これらの失敗を性能結果として使わない。既存の検査は削除・弱化していない。

ローカルでは、portable の200モデルについて、境界の4095／4096 byte、SHA-256、引用符を含む位置、ボイスの検証済み共有、一般配列の複写、直接変更、証拠のない記述の拒否を確認した。Windowsでは200ボイス・18000フレームの依存、変更範囲、同じ内容への復元、先読みと通常描画の字幕画素一致を検証する。

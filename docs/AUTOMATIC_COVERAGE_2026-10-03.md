# 自動でキャッシュの対象になるもの・ならないもの（2026-10-03）

「外部プラグイン、PSD、外部画像、外部図形、連番画像、フォントなど、外部のものはどこまで自動で対象になるか」をまとめた。今回、連番画像とフォント（代替フォントを含む）を自動の対象にした。対象にならないものは、そのアイテムが映る区間だけ通常描画（YMM4 がそのまま描く）になり、ほかの区間は対象のまま。

## 1. 今回、自動の対象にしたもの

| 対象 | 以前 | 今回 |
| --- | --- | --- |
| 連番画像（動画アイテムに `shot0.png` のような番号付きの画像を指定し、YMM4 の連番読込で再生するもの） | 読込の完了を確認できないため、映る区間は保存しなかった | 各フレームは、そのとき表示する 1 枚だけに依存する。描画後、キーが示す画像を実際に表示したことを確かめてから保存する |
| DirectWrite にないファミリーで描く文字、フォントにない文字（代替フォント） | DirectWrite にないファミリーは通常描画。文字単位の代替は追っていなかった | 文字を描くアイテムのキーに、インストール済みフォント全体の識別を入れて対象にした |
| Community の ShuffleText・ShuffleTextInOut・数値テキスト | フォントをキーにできないため通常描画 | コードを読み、対象にした。「フォント」のファイル、数値テキストは数値の書式（カルチャ）もキーに入れる |

### 連番画像の仕組み

- 表示する画像は、YMM4 自身の時間の計算（`VideoSource.CalculateSourceTime`）をそのまま呼んで求める。再生速度とそのアニメーション、開始位置、ループに従う。連番は 1 秒 60 枚で、YMM4 の連番読込と同じ規則で一覧を作る（同じ名前・拡張子で、番号が途切れずに続く範囲）。YMM4 は、同じ名前で番号が最も小さいファイルを指定したときだけ連番として再生する（途中の番号のファイルでは一覧が空になる）。
- 表示する画像が変わる所で区間を分けるので、画像を 1 枚差し替えても、その画像を表示するフレームだけが対象から外れる（YMM4 は読み込み済みの古い画像を表示し得るので、ほかの素材と同じく再起動まで通常描画）。
- 全画像を背景で指紋（内容のハッシュ）にかける。1 プロジェクトの素材の上限は 65,536 ファイルにした（以前は 4,096）。
- 起動中に連番の枚数や番号が変わると、YMM4 は読み込み済みの一覧を使い続け得る。そのアイテムは再起動まで通常描画する。
- 読めない画像（どの読込プラグインも開けない）は、YMM4 が空の画像を描く。そのフレームは保存しない。
- シーンアイテムの中の連番は、そのフレームが全画像に依存する。1 フレームの依存が 256 ファイルを超えると通常描画になる。

### フォントの仕組み

- フォント名は YMM4 と同じくフォント設定から引き、一覧にない名前は Arial で描く（YMM4 と同じ）。ファミリー・太さ・スタイル・幅をキーに入れ、ファミリーのファイルを指紋にかける。
- 代替フォントは、文字ごとにどのフォントが使われたかを追う代わりに、インストール済みフォント全体（DirectWrite のシステムのフォントセットの、ファイルのパス・サイズ・更新時刻）の識別をキーに入れる。フォントを追加・削除・更新すると、10 秒以内か次の記述時に検出し、文字を描く区間のキーだけが変わる（その区間は描き直す）。
- 数値テキストは、値の書式（小数点・桁区切りなど）が Windows の地域設定で変わる。描画するスレッドの書式が記述時と違えば、その区間は通常描画にする（4.56.1.0 の YMM4 は表示言語だけを設定し、数値の書式は OS の設定のまま）。

### 前回の説明の訂正

前回「インストールされていないフォントを使うアイテムは対象外」と書いたのは不正確だった。YMM4 は一覧にない名前を Arial で描くので、キャッシュも Arial として対象だった。対象外だったのは、次の 3 つだけだった。

- フォント設定の項目が、DirectWrite にないファミリー名を指している場合
- フォントのファイルがローカルにない場合
- Community の ShuffleText・ShuffleTextInOut・数値テキスト

文字単位の代替フォントは追っていなかった（今回キーに入れた）。

## 2. 以前から自動の対象のもの

| 対象 | 備考 |
| --- | --- |
| 画像（PNG・JPEG など、WIC で読むもの）、GIF・WebP | ファイルの指紋 |
| PSD 画像（立ち絵ではない画像アイテム）、SVG 図形 | 同梱の読込プラグイン。ファイルの指紋 |
| 動画（Media Foundation・FFmpeg） | デコードが要求時刻まで終わったことを確かめてから保存 |
| テキスト・字幕（文字装飾・制御タグ・「*」置換を含む） | フォントは上のとおり |
| Community で読んだ処理（約 70 種） | PDF ページ、レンズフレア、ブルームなど。一覧は [KnownCode.cs](../NVEncVideoWriterPlugin/KnownCode.cs) |
| 同一性を種にする乱数（ランダム移動、CameraShake など） | その起動中のそのアイテムに限ってキーにする |
| 信頼した外部プラグイン | 設定で個別に信頼したもの。アセンブリの MVID をキーに入れる |

## 3. どうしても自動では対象にできないもの

| 対象 | 理由 |
| --- | --- |
| 未確認の外部プラグインのコード（エフェクト・図形・アイテム・トランジション・ブラシ・読込プラグイン） | 中で何を読むか（時計、乱数、ネットワーク、報告しないファイル、前のフレーム）を確かめる方法がない。同じ入力で同じ絵になる保証がない。設定で「信頼」すれば対象にできる（その前提は利用者の判断） |
| OpenFX・VST3 | 外部のネイティブのプログラムを動かす。中身を確かめられないので、信頼設定でも対象外 |
| 残像（AfterImage）・モーションブラー（MotionBlur） | 直前に描いたフレームの画像を使う。同じ時刻でも、その前に何を描いたかで結果が変わり、1 フレーム単位の保存と両立しない |
| 文字の「ランダム」順の表示（テキスト・字幕） | YMM4 自身が、アイテムが画面に入り直すたびに別の乱数で描く。YMM4 の描画そのものが毎回変わるので、「YMM4 と同じ絵」を保証できない |
| インターネット上の素材、クラウドの「オンラインのみ」のファイル | 読むたびに内容が変わり得る、または読むとダウンロードが走る。内容を確かめられない |

## 4. できるが、まだ対象にしていないもの

| 対象 | 必要な作業 |
| --- | --- |
| 立ち絵（AnimationTachie・PSD 立ち絵・シンプル立ち絵） | 口パクの音量は非同期に計算され、YMM4 は待ち時間を超えると無音で描く。完了を確かめる仕組みが要る。PSD 立ち絵は目パチ・口パクの設定がプロジェクト外のファイルにある。まばたきの間隔が既定のとき、乱数の種がフォルダー名の文字列ハッシュ（起動ごとに変わる）なので、その起動中だけのキーにする。部品のファイルも依存に入れる。シンプル立ち絵は音量を使わないので比較的容易 |
| DirectShow で読む動画 | 読込処理に Harmony で確認を差し込めない（例外フィルターを作り直せない）。別の確認方法が要る |
| Community の LUT・グラデーションマップ | 使うファイルを YMM4 に報告しない。設定値からファイルを拾えば対象にできる |
| Community のグループ制御（ArrangeGroupItems など）・Container・シーンのブラシ | ほかのアイテムやシーンを描く。依存の範囲を広げれば対象にできる |
| Community の未読の処理（DirectionalColorKey、FillSameground、FillSametype、ParticleOutput、Particlize、PuppetDeformation、VectorFieldWarp、Pen） | コードを読めば判断できる |
| MIDI の音声 | SoundFont と設定をキーに入れれば、音声を読む区間（シーンアイテム・音声波形）も対象にできる |

## 5. 検査

実際の YMM4 Lite 4.56.1.0 と WARP（ソフトウェア描画）で確かめた（[cache-development](../.github/workflows/cache-development.yml)）。

- 連番画像（HostCacheProbe）: 生成した PNG 12 枚を 30 fps の動画アイテムで再生。キャッシュなしの描画と、ストアから復元した 6 フレームが画素ごとに一致。キーが次の画像を示すように細工すると、全フレームが描画はされるが保存されない（完成判定が理由を表示）。細工を外すと再び保存される
- 連番画像（CacheChecks）: 各フレームの依存が表示する 1 枚だけ（30・60 fps、ループ、再生速度 50%）。画像を上書きするとそのフレームだけ対象外、ほかのフレームのキーは不変。起動中にファイルが増えると対象外、元に戻ると対象
- フォント（CacheChecks）: インストール済みフォントの識別が取れて安定。DirectWrite にないファミリーへ割り当てた名前も対象になり、元のファミリーと別のキー。Community の 3 種がフォントのファイルに依存し、数値テキストだけが書式に依存。別の書式のスレッドでは数値テキストの区間だけ通常描画
- 完成判定（ReadinessChecks）: 連番は画像を読み込んだときだけ完成。キーが示す画像を表示していなければ未完成。先読みで余分に表示した画像は影響しない

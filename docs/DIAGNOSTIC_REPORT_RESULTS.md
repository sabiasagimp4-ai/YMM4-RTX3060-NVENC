# 診断レポートと GitHub 報告

2026-10-05。main `a2280ef9dc43bd844429a52e7c113a9b5b50502b` を基準に、[計画](DIAGNOSTIC_REPORT_PLAN.md)を実装。ブランチ `codex/diagnostic-issue-report`。レビュー用 Draft PR とし、マージ・リリースは行わない。

## 利用手順

ツール「描画キャッシュ」で「問題を報告」を押すと、GitHub に渡す本文と詳細レポートを読み取り専用で表示する。環境情報だけの手動報告も可能。「詳細をコピー」「詳細を保存」はアカウント不要。

「GitHub の報告画面を開く」を押した時点で表示した本文が GitHub へ渡る。利用者がログインし、症状・再現手順を記入して投稿する。1800 文字を超える URL は作らず、長いレポートは要約を送る。詳細は確認したうえでコピーして本文へ貼り付ける。実際の投稿・Issue の検索や重複統合はプラグインから行わない。

ウィンドウを開くだけでは送信・ファイル保存・クリップボード変更をしない。ブラウザー・保存・コピーの失敗は画面内に一般的な案内を出す。保存を取り消した場合は書き込まない。

## 収集する情報

- YMM4 とプラグインの数値バージョン、MVID、Windows/.NET の数値バージョンとプロセスのアーキテクチャ。
- 使用可能な機能のビット、プレビュー・出力キャッシュ・NVENC の設定状態。
- 既に観測した GPU の vendor/device 番号、専用 VRAM、ソフトウェアアダプターかどうか。未観測なら未取得。ドライバーバージョンは収集しない。新規 GPU デバイスは作らない。
- 問題の段階・種別、固定の例外カテゴリ、HRESULT、回数、プラグイン自身の最大 8 個のメソッドトークン。トークンはプラグインの MVID と対応させて調査する。

例外の Message/Data/ToString、型名・メソッド名・ソースパス、素材・プロジェクト本文や ID、ユーザー名、生ログは収集しない。未知の例外型は ExternalException とする。プラグインのバージョン文字列は数値と限定した prerelease/hash 形式のみ許可する。

端末内のセッションで最大 32 種類を保持し、同じ段階・種別・例外カテゴリ・HRESULT は回数へ集約する。例外オブジェクト、付随データ、ホストや GPU オブジェクトを保持しない。記録が混雑した場合や上限を超えた場合は省略件数だけを残す。画面を閉じてもセッションの集計は残り、終了すると消える。

## 記録の範囲と限界

未読の本体で契約に合わずキャッシュが使えない場合、一部機能だけ使えない場合、フックの接続失敗と、既にプラグインが捕捉する描画キャッシュ・先読み・設定保存・エンコード処理の予期しない例外を対象にした。通常の対象外フレーム、ロード待ち、取消、既知の解像度・GPU・コーデック・ドライバー制限は記録しない。既存の回復・取消保護・資源解放処理を維持する。

新しい全体例外ハンドラーは設置しない。プラグインをロードできない古い .NET/本体、突然終了、ドライバー停止、致命的なメモリ不足や既存の捕捉箇所以外の例外は自動収集を保証しない。対応バージョンやロード互換性の拡張ではない。診断レポートは詳細ログと別で、生ログを自動添付しない。

## 検証

`tests/DiagnosticChecks` は portable で実行する。秘密を含む例外の Message/ToString を呼ぶと失敗する反例、偽スタックと Data、例外の GC 回収、10 万回の重複、32 種類上限、並行記録/スナップショット、バージョン文字列の注入、不正 URL と長い本文の要約、表示本文と URL 本文の一致を検査する。

`HostCacheProbe --diagnostic-ui-check` は Windows STA の WPF で、読み取り専用プレビュー、無操作時の副作用ゼロ、コピー・保存取消・非同期保存・各操作の失敗、不正な送信先の拒否、実プラグインのツール導線を fake action で検査する。ブラウザーを起動したり、実際の報告を投稿したりしない。`--integration` は実ホストの契約拒否で診断が増え、正常な接続では増えないことを検査する。

通常 CI に追加し、既存の画素・先読み・GPU 保持・native 検査も維持した。固定の過去 commit を測る 8 手順は従来どおり `measure_baselines=true` の手動実行時だけ。最終 commit の実行 URL と結果は PR に記録する。Windows WPF 検査は fake action の検査であり、実機のクリップボード・既定ブラウザー・GitHub のログイン UI・RTX の動作確認を代替しない。

## 今後

Issue の同一署名による検索・重複統合、記録箇所の拡張、ドライバー情報、完全自動報告は次段階。自動報告には受付サーバー、明示的な有効化、認証管理、迷惑投稿防止を別途設計する。初版はサーバー・トークン・自動投稿を導入しない。

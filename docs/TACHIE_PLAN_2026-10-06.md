# 立ち絵とアイテムの重なりの対応計画（2026-10-06）

目的は、いま通常描画に回している次のものを、描画キャッシュの対象にすること。必須はグループ制御・シーンアイテム・差分合成。

- グループ制御の中の立ち絵（グループ制御・合成グループ）
- シーンアイテム（入れ子）の中の立ち絵
- 差分合成（動く立ち絵）
- 同じレイヤーで表情が重なるもの
- 付属 INI（動く立ち絵のパーツごとの合成設定）
- 同じレイヤーで時間が重なるアイテム（立ち絵以外も）
- 立ち絵の全体: まばたき（起動ごとに変わる）、停止中の先読み、古い版（4.47.0.0〜4.56.0.1）

基準は YMM4 Lite 4.56.1.0 のコード（`docs/HOST_CONTRACTS.md` の方法）。各段階で、キーの検査（CacheChecks）と実ホストでの画素の一致（HostCacheProbe）を足してから次へ進む。

## YMM4 のコードで分かったこと

### 描画の順番（同じレイヤーの重なり）

- `TimelineSource.GetOrderedTimelineResources` が描く順を決める。並べ替えのキーは「常に手前」「Z 順（有効なときだけ、描いた結果の Z）」「レイヤー」の 3 つだけ。
- 3 つとも同じアイテムは、内部の辞書（`timelineResources`）の列挙順で描かれる。辞書への追加は、先読み（`prefetchedResources`）・並列の作成（`AsParallel`、順序なし）・削除後の空き枠の再利用で決まるので、シークの履歴で変わる。**YMM4 自身が、同じレイヤーで重なるアイテムを描くたびに違う順で重ね得る**。いまのプラグインはこれを確かめられないので、その区間を通常描画にしている（`FrameDependencyIndex`、ambiguousOrder）。
- 選択枠（`TimelineItemRects`）も同じ順を使う。

### 表情の選び方

- `TimelineSource.UpdateResources` が、そのフレームの表情・ボイス（`PickFaceItems`、タイムラインのアイテム一覧の順）をキャラクターごとに集め、レイヤーの降順（安定な並べ替え）にする。先頭が表情、ボイスは最初のもの。同じレイヤーの表情は、アイテム一覧の順になる（こちらは決まった順）。
- 表情（`TachieFaceItem`）は描画されない（`IVideoItem` ではない）。

### グループ制御

- 通常のグループ制御: 子のアイテムは親のタイムラインで描かれ、グループのエフェクトが `ParentEffects` として掛かる（子の中の番号と数つき。`TimelineGroupResolver`）。立ち絵の描画器は親の `timelineResources` にある。
- 合成グループ（`IsComposite`）: 子は `CompositeSource` が持つ別の `TimelineSource`（同じシーン、`CompositeItemPicker(groupItem)`）で描かれる。表情はタイムライン全体から選ぶ（グループの終わりでフレームを止めるが、グループが表示中のときは同じ）。立ち絵の描画器は、その内側の `TimelineSource` の `timelineResources` にある。
- いまのプラグインは、タイムラインにグループ制御が 1 つでもあると、3 種の立ち絵すべてを通常描画にしている。描画器を親のタイムラインだけで探しているため（`SafeSource`）。

### シーンアイテム

- `SceneSource` が、別のシーンの `TimelineSource` を、シーンアイテムの再生位置・速度で更新する。立ち絵と表情・ボイスは、そのシーンのタイムラインから選ばれる。
- 動く立ち絵・PSD 立ち絵は、ルートのタイムラインだけを対象にしている（`TryFiles` の root 条件、`SafeSource`、停止中の先読みの判定 `ContainsNative`）。シンプル立ち絵の範囲計算は入れ子のタイムラインでも動くが、グループ制御の条件は同じ。
- 口パクの完成判定（`NativeTachieReadiness`）は、入れ子の描画器の更新もルートのフレームの範囲で観察できる（`AsyncLocal`）。

### 差分合成

- 動く立ち絵の `ItemParameter.IsDifferentialComposite`。パーツごとに、表示中の表情（レイヤーの降順）のうち最初に指定のあるものを使い、なければアイテムの指定を使う。
- 使い得るパーツは、すべての表情とアイテムのパーツ（いまの依存の集め方と同じ）。どのパーツになるかは、そのフレームの表情の並び（キーに入っている）で決まる。

### 付属 INI

- パーツの画像 `X.png` の隣の `X.ini`（Shift-JIS、`blend`・`opacity`・`placeon`）。`LayerConfig.Load` が、パーツのパスが変わったときだけ読む。
- YMM4 の読み込みには癖がある: ファイルがあるとき既定値に戻さずに読むので、前に読んだ INI の値が残る（読んだ履歴で結果が変わる）。`opacity` は実行中のカルチャで数値にする。
- いまのプラグインは、INI があると対象外にしている（一覧に `.ini` があれば不可、描画器の設定が既定値でなければ不可）。

### まばたき

- 動く立ち絵は素材フォルダーのパス、PSD 立ち絵は PSD のパスの `string.GetHashCode()` を種にする。.NET はこの値を起動ごとに変えるので、まばたきの時刻が起動ごとに変わる。いまは、その起動の間だけのキー（`animation-blink-session`、`psd-blink-session`）にしている。

### 古い版

- 立ち絵のコードの照合（`HostContracts` の `simple-tachie` などの digest）は、4.55.1.0〜4.56.0.1 のシンプル立ち絵、4.56.0.0〜4.56.0.1 の動く立ち絵・PSD 立ち絵が 4.56.1.0 と同じ。いまは同梱の DLL の識別子（MVID）が 4.56.1.0 と同じときだけ使うので、外れている。
- 口パクは版で 3 通り: 4.54.0.1 以前は描画の中で音声を同期で読む（待ちがない）、4.55.0.0〜4.55.0.1 は非同期（セッションなし）、4.55.1.0 以降は `LipSyncEnvelopeSession`（いまの完成判定の対象）。4.56.0.x と 4.56.1.0 の間にも差がある。

## 段階

| 段階 | 内容 | 主な変更 | 検査 |
| --- | --- | --- | --- |
| 1 | 同じレイヤーの重なりの順を決める | `GetOrderedTimelineResources` の結果を、同じキーの中でアイテム一覧の順に並べ直す（YMM4 の順のうち、決まっていない部分だけ）。キーに、重なる組のアイテム一覧の順を入れる。入らないときは今までどおり通常描画 | 並べ替えで順が変わるとキーが変わる。実ホストで、重なる 2 アイテムを、シークの順を変えて描いても同じ画素、並べ替えると変わる |
| 2 | グループ制御の中の立ち絵 | 3 種の「グループがあれば対象外」をやめる。描画器の確認（`SafeSource`）を、合成グループの内側の `TimelineSource` までたどる | 通常・合成グループの中の 3 種の立ち絵で、キャッシュの画素が通常描画と一致。グループの設定・子の数を変えるとキーが変わる |
| 3 | シーンアイテムの中の立ち絵 | 動く立ち絵・PSD 立ち絵を入れ子のタイムラインでも対象にする。確認を `SceneSource` の内側までたどる（深さに上限）。停止中の先読みの判定を入れ子まで見る | 入れ子の 3 種の立ち絵で画素が一致。入れ子の中を編集するとキーが変わる。先読みは口パクの計算枠を使わない |
| 4 | 差分合成 | 差分合成を対象にする | 表情を 2 つ重ねた差分合成で、表示中の表情の組が変わるフレームを含めて画素が一致 |
| 5 | 同じレイヤーで重なる表情 | 段階 1 の順をキーに入れたうえで、3 種の「同じレイヤーの表情は対象外」をやめる | 同じレイヤーの表情を入れ替えるとキーが変わり、画素が一致 |
| 6 | 付属 INI | `.ini` を依存（指紋）に入れる。保存の前に、各レイヤーの設定が、今の INI を既定値から読み直した値と同じことを確かめる（読んだ履歴で値が残っているとき、カルチャで読み方が変わるときは保存しない） | blend・opacity・placeon の INI で画素が一致。INI を書き換えると保存しない |
| 7 | まばたきの種をそろえる | 動く立ち絵・PSD 立ち絵のまばたきの種（パスの `GetHashCode`）を、起動に依らない値に置き換える（`RandomSeedAlignment` と同じ方法）。起動の間だけのキーをやめ、再起動後もディスクのキャッシュを使う | 2 回の起動でまばたきの画素が一致。再起動後にディスクから出る |
| 8 | 停止中の先読み | 動く立ち絵・PSD 立ち絵のうち、ボイスが重ならない区間（口パクの計算を始めない）を先読みする | 先読みで描いたフレームが通常描画と一致し、口パクの計算が始まらない |
| 9 | 古い版の立ち絵 | 立ち絵の判定を MVID から、照合した digest（確かめた版の記録）に変える。まず 4.55.1.0〜4.56.0.1（コードが同じもの、口パクの差分を読む）、次に 4.54.0.1 以前（同期の口パク）。4.55.0.0〜4.55.0.1 は口パクの判定を作るか対象外にする | 代表の版の実ホストで、3 種の画素の一致 |
| 10 | 仕上げ | README の表、`CACHE_BEHAVIOR.md`、`HOST_CONTRACTS.md`、リリース | — |

## 守ること

- 確かめられないものは今までどおり通常描画にする（どの段階でも、条件に合わなければ以前の扱いに戻る）。
- YMM4 の描画を変えるのは、YMM4 自身の結果が決まっていない部分だけ（同じレイヤーの重なりの順、まばたきの種）。どちらも、プラグインを入れている間は毎回同じ結果になる。
- 動画パーツ（動く立ち絵の動画の部品）と、他の作者の立ち絵プラグインは、この計画の対象外。

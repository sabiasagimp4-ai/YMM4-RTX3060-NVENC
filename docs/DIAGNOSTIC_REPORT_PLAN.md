# 診断レポートと GitHub 報告の計画

基準: main `a2280ef9dc43bd844429a52e7c113a9b5b50502b`（preview.3）。実装ブランチ: `codex/diagnostic-issue-report`。Draft PR とし、main・release・tag は変更しない。

## 利用者の選択と動作

初版は GitHub ログイン方式。問題を端末内で集約し、ツール「描画キャッシュ」の「問題を報告」から内容を確認する。コピー・Markdown 保存・GitHub の投稿画面を開く操作を用意する。投稿は利用者が GitHub で行う。診断の確認・保存にはアカウント不要。自動投稿・受付サーバー・トークンの保存は行わない。

## 実装

1. 未確認の本体/同梱版で契約を満たさない機能、接続失敗、プラグイン内で捕えた予期しない例外を記録する。通常の対象外フレーム、ロード待ち、既知の設定/ハードウェア制限、キャンセルは問題に数えない。
2. 端末内の最大32種類、各最大8個の自身の呼び出し箇所。同じ機能・種類・例外カテゴリ・HRESULTを集約する。元の例外やホスト/描画オブジェクトを保持しない。混雑時は記録を省き、描画スレッドで待たない。
3. 報告には型付きの環境情報だけを渡す。バージョン、既知モジュールのMVID、CPUアーキテクチャ、観測済みGPUのvendor/device/専用VRAM、機能の有効状態。例外のMessage/Data/ToString、パス、素材・本文・プロジェクトID、ユーザー名、生ログは使わない。GPUを観測していない場合や未取得のdriverはunknownとし、診断のために新しいデバイスを作らない。
4. 読み取り専用の詳細レポートとGitHubへ渡す本文を表示する。GitHub URLは固定のリポジトリのissues/newのみ、全パラメーターをエスケープし、1800文字以下。長い場合は要約だけを入れ、詳細を明示操作でコピー/保存できる。GitHubを開く時点で本文がGitHubへ送られること、ログインと最後の投稿操作が必要なことを表示する。
5. 保存・クリップボード・ブラウザー失敗は報告画面内で扱い、描画/出力の処理・資源解放・キャンセル保護を変更しない。勝手にブラウザーや確認画面を開かない。

## 検証と完了条件

- portable: 悪意ある例外メッセージ/データ/スタック、改ざんされたバージョン、URL特殊文字、取消、同一エラーの連打、上限超過と並行記録。
- Windows: real host に対するビルド、WPF の確認/コピー/保存/報告操作と操作失敗を fake action で検査し、実際のブラウザーやIssueは作らない。ツールの導線も検査する。
- 既存の通常CIを維持。fixed baseline の計測は従来どおり手動入力時だけ。任意RTXは実機成功と数えない。
- 最終headの検査と結果をPR/結果文書へ記録し、Draft・未マージで引き継ぐ。

## 限界と次の段階

プラグインをロードできない場合、プロセスの突然終了、OS/driver停止や致命的なメモリ不足は自動収集を保証しない。今回ロード互換性や対応バージョンを拡張しない。完全自動投稿は、受付サーバー・利用者の明示的な有効化・認証情報の管理・迷惑投稿防止・重複Issue集約を別途設計する。

# 描画キャッシュの仕様

2026-10-04の監査ブランチの実装を含む仕様。入口は [README](../README.md)、開発課題は [AE_CACHE_DEVELOPMENT.md](AE_CACHE_DEVELOPMENT.md)、設計判断と残る問題は [アーキテクチャ監査](CACHE_ARCHITECTURE_AUDIT_2026-10-04.md)。

素材の変更通知だけで保存済みフレームを採用する方式は使わない。通知が処理される前でも、作り直したYMM4のsourceは新しい画像を描き得ることを実ホストで確認した。30秒の背景再確認も、この未検出の間隔をなくさない。保存済みフレームでも、そのフレームの素材を同期leaseで確認して書き込み・置換を防ぐ扱いを維持する（[高速化項目4の検討](SPEEDUP_RESULTS_2026-10.md)）。

## 保存と供給

標準プレビューの再生・一時停止・シークと、動画出力で完成した合成済みフレームを保存する。デコードが要求時刻まで完了したと確認できない場合は保存しない。判定とホスト互換性は [HOST_CONTRACTS.md](HOST_CONTRACTS.md)。

RAM／ディスクから復元したプレビュー画像と、読み戻し完了を確認した表示中の保存用コピーを、予算と利用履歴に応じてGPU上に保持する。表示が先に切り替わったコピーはRAMだけへ保存する。保持した画像の再利用ではCopyFromMemoryを省ける。初回レンダーのCPU readbackは残り、ホストの可変effect graphをそのまま保持することはしない。 ライブプレビューのreadbackは実際のD2D描画先と同じD3D11 deviceのstaging textureへコピーし、`Map(Read, DoNotWait)`で完了を確認する。GPU処理中は待たず、次の描画タスク更新で再試行する。各sourceで保留は3枚までとし、3枚ともGPU処理中のときだけ新しい保存を省略する。保存するフレームは一度だけ描き、保存用に描いた画素をそのまま表示する。未完成画像は保存しない。消去・編集・入力変更後の古いコピーも採用しない。動画出力のフレームも同じ方式（各sourceで保留3枚まで、プールなし）で保存し、GPUの完了を毎フレーム待たない。3枚とも保留中なら最も古い1枚（3フレーム前）の完了を待つため、出力した全フレームを保存する。出力の最後に残った保留分は、出力用のsourceを破棄するときに完了させて保存する。明示的なcaptureとidle先読みは同期完了を使う。[GPU保持の設計](GPU_FRAME_RETENTION.md) を参照。
保存用コピーを表示した次の通常Update（miss・bypass）では、ホストの元のoutputへ戻してからコピーを解放する。ホストが元のcommand listを通常どおり解放するため、初回保存のたびに元の描画graphが蓄積することを防ぐ。再利用するUpdateではこの復帰は行わない。


ディスクI/O、初期化、索引、整合性検査は専用workerで行う。読込は書込より優先し、実測読込費用に応じて再生位置の0.5〜2秒先まで先読みする（最大120フレーム、窓は半RAM予算でも制限）。一時停止時は描画タスク上で最大50 msの読込を待ち、間に合わなければ通常描画する。起動直後に索引を読み込んでいる間は、索引にまだ無いフレームのために待たない。再起動後のディスクLRUは、各レコードの最終書込時刻（ディスクから読んだときにも更新する）の順に組み立て、容量を超える分は最も古く使われたものから消す。消去は保存世代を永続化し、削除できなかった旧ファイルが次回起動で復活することを防ぐ。永続化失敗はツールに表示する。

## メモリと容量

| 対象 | 現行の上限・方式 |
| --- | --- |
| RAM設定上限 | 既定2048 MiB、64〜16384 MiB。自動調整または手動固定 |
| RAMストア | LRU、最大1024 entry。借用中の不変画素は退避後も有効 |
| ディスク | 4 GiB、Brotliによる無損失圧縮／raw fallback |
| 1フレーム | 128 MiB（保存ヘッダーを含む） |
| ディスクキュー | 128件、待機中の書込画素128 MiB。満杯なら追加保存を省略 |
| GPU保持 | 描画に使うGPUのVRAMに応じた自動配分（初期128 MiB、OS予算から余裕を残す、設定上限の既定Auto・最大8192 MiB）か、上限での手動固定。entry数は予算に比例して64〜1024。画像総予約は保持＋256 MiB |

GPU予算は画素payloadの予約であり、ドライバーの実VRAM全量ではない。

VRAMの自動配分は、描画スレッド外で1秒ごとに、描画に使うアダプターの値を `IDXGIAdapter3::QueryVideoMemoryInfo`（ローカル）で採取する。採取するのは、このプロセスへのOSの予算と現在の使用量。

- 保持の目標は「予算 −（YMM4の保持以外の使用量）− 余裕」とする。余裕は max(1 GiB, 予算の1/5)。
- 目標は、搭載 dedicated VRAM の1/2と設定上限で抑える。測定済みの少量専用メモリも1/2を越えない。測定できた専用メモリが0の内蔵GPUは自動のGPU保持上限も0で、128 MiBの下限を設けない。RAMキャッシュからの表示は引き続き利用できる。旧設定の自動・2048 MiBは一度だけAutoへ移し、移行済み marker を保存する。手動と他の明示的上限、移行後に選び直した2048 MiBは維持する。新規設定の上限はAuto（最大8192 MiB）。保存済みの明示的な上限は維持し、Autoを手動へ切り替えると2048 MiBを選ぶ。
- 使用量が「予算 − 余裕の半分」を超えたら、直ちに半分以下にする。
- 健康なサンプルが3回続くごとに128 MiBずつ増やす。
- ソフトウェア描画（WARP）や取得に失敗したときは、値を保ち、増やさない。
- 予算を下げても、保持フレームの解放は次の描画（Update）で描画スレッドが行う。

再生中のGPU先回り転送は、同じ描画スレッドの直前Update＋Drawに余裕があり、保持の空きがある場合だけ、次の4候補からRAMにある1枚までを上げる。ディスクの完了を待たず、既存の保持を追い出さない。転送前後のgenerationとrevisionを確認し、実際に使うときは通常のcapture・ファイル検証を行う。停止中は転送しない。アイテム選択操作により通常描画へ戻る経路も転送しない。詳細ログの「先回り転送」とtraceの `gpu-read-ahead` で確認できる。

認識したDXGI/D2Dのdevice lostではGPU保持を捨て、失われた描画器の素材をプールへ戻さない。ホストがまだ参照する表示の所有権は次の通常Update・破棄で返す。対象の描画器は作り直されるまで通常描画にし、新しい描画器は再びキャッシュできる。模擬通知はCIで検査するが、実際のドライバー障害と復旧は実機での確認が必要。

自動RAM配分は描画スレッド外で1秒ごとにOS空き物理RAM・process private bytes・managed heap・GC上限を採取する。設定上限と物理RAMの1/4以下を予算とし、OSへ最大(1 GiB, 物理RAMの1/8)を残す。プロセス全体は物理RAMの1/2を目安にし、書込キューと最大1フレームの余裕も確保する。圧力時は直ちに縮小し、健康なサンプルが3回続いた回復時には128 MiBずつ増やす。取得失敗では増やさない。

RAM縮小でも有効なディスクレコードは残す。借用配列、書込キュー、YMM4本体、デコーダーはRAMストアの使用量とは別で、縮小直後にプロセス使用量が下がるとは限らない。GCを強制実行しない。

1080p BGRAでは256 MiBが約32枚、2 GiBが約258枚の画素量に相当する。全区間を巡回できても、全フレームを同時に保持できるとは限らない。

## 停止中の先読みと帯

停止中は最後の操作から既定8秒後に30フレームずつ設定範囲（既定はタイムライン全体）を巡回する。巡回するタイムラインはツール「描画キャッシュ」から受け取るため、ツールを開いている間だけ動く。開始フレームと終了フレームを設定でき、終了は含まない。終了0は末尾。現在位置から末尾→先頭、現在位置の前後、先頭からの順序を選べる。停止中の先読みだけを無効にもできる。

保存済み・恒久的に通常描画が必要なフレーム、複製すると状態が変わるフレームは飛ばす。入力（キー・クリック・ホイール・ドラッグ。ボタンを押さないマウスの移動は数えない）・編集・シーク・再生・ビュー変更・消去で中断し、次の有効な状態で再開する。未完成デコード等で保存できなかったフレームを無期限に再試行するものではない。

緑はRAM、青はディスクの保存状態。ツールはタイムライン全体、対応ホストのルーラーは表示範囲に帯を出す。帯は現在のviewportのキーに対応する表示であり、実際の表示FPSや全フレーム検査の証明ではない。帯は250 msごとに確認するが、保存内容・フレームのキー・表示範囲が変わらない間は照会を省く（最長2秒ごとには照会し直す）。

## キーと無効化

同じIsAlwaysOnTop・Layerの動画アイテムが重なるフレームは、要求前に描画順を確定できないため通常描画する。YMM4のresource dictionaryの挿入順はprefetch／並行resource作成／seek履歴の影響を受け得る。モデル配列順をキーに足すだけでは証明にならない。トランジションの参照先と入れ子・全体依存にもこの判定を伝える。Z値が実際には異なる場合も保守的に対象外となり、今後の描画順証明で改善できる余地がある。

同じsourceの直前出力を返す経路も、RAM／GPU復元と同様に入力captureを再検証する。code信頼・font世代・reader・描画設定・scene親のwitnessを確認し、provider callback後にもrevisionと環境を再確認する。capture前後の検証は、ホストの可変モデルを原子的にsnapshotできることの証明ではない。

キーは正確な時刻ticks（100 ns）、fps、usage、描画環境、viewport、モデル、素材の指紋から作る。永続schemaは `pixels-v7`。GPU・ドライバー・プラグインのビルドが変われば以前の画素は再利用しない。

通常は全体設定とそのフレームに重なるアイテムを依存に含める。トランジションは直前フレームのアイテムも追う。シーンアイテムと音声波形図形の区間はプロジェクト全体に依存する。描画に使う補間、読込方式、音声アップサンプリング、拡張子設定、フォント設定、テキスト／字幕の「*」置換もキーに含める。レイヤーの名前と色は描画しないためキーに含めない。ルートのタイムラインのレイヤー音量は、音声を読む区間（シーンアイテム・音声波形）のキーだけに含める。非表示のレイヤーは全区間のキーに含める。

編集後250 ms以内は通常描画し、変更が落ち着いてから記述し直す。YMM4の設定のうち描画に使わない項目（タイムラインの拡大率、プレビューの音量、画面の配置など）の変更では記述し直さない。無関係な区間の内容キーを保ち、Undo後も一致した状態を再利用する。記述処理はまだwhole-project JSONを起点とし、モデル上限は16×1024×1024文字。完全な差分記述は未実装。

記述の中の4 KiB以上の埋め込み配列（ボイスの圧縮WAVを含む）は、その内容のSHA-256で表す。プロジェクトの保存形式とYMM4のJSON設定は変更しない。同じ配列は1回の記述の中で一度だけハッシュし、次の記述では再確認するため、配列の中身を直接変えた場合も新しい記述へ反映される。停止中の先読みの複製には、記述に結び付いた元のデータを、内容が一致したと確認して渡す。4.56.1.0の標準ボイスはホストが読み取り専用で使う配列を共有し、それ以外の配列は複写する。JSONに入らない音声の一時ファイルのパスも複製へ渡し、パスが変わったcaptureは採用しない。元のデータがない記述、記述の後にデータが変わった複製は先読みしない。

素材の背景検証は最大65,536ファイル（連番画像の全画像を含む）。要求フレームで使う素材から検証し、採用時にもファイルleaseとキーの指紋を照合する。確認できないファイル（リンクやクラウドの代替ファイルを含む場所、NTFS以外やネットワークのドライブ、4 GiB超、見つからない、読めない）は依存区間だけ通常描画にし、停止中の先読みはその区間を飛ばす。そのファイルだけを30秒ごと、または有無・サイズ・更新時刻が変わったときに確認し直す（プロジェクト全体は確認し直さない）。

YMM4起動中に同名素材を上書きすると、ホストは読み込み済みの古い内容を保持し得る。変更を検出したファイルを使う区間は、内容を戻しても再起動まで通常描画する。キャッシュ無効中で、まだ検証していない間の上書きは検出できない。

連番画像（動画アイテムに番号付きの画像を指定し、YMM4の連番読込で再生するもの）は、各フレームが表示する1枚だけに依存する。表示する画像はYMM4自身の時間計算（再生速度とそのアニメーション、開始位置、ループ）で求め、描画後に実際にその画像が表示されたことを確かめてから保存する。画像を差し替えると、その画像を表示するフレームだけが対象から外れる（上と同じく再起動まで）。起動中に連番の枚数や番号が変わると、YMM4は読み込み済みの一覧を使い続け得るため、そのアイテムは再起動まで通常描画する。シーンアイテムの中の連番は、そのフレームが全画像に依存する（1フレームの依存が256ファイルを超えると通常描画）。

## 外部処理・フォント・乱数

未監査のエフェクト・図形・アイテム・トランジション・ブラシは依存するアイテムの区間だけ通常描画する。自動対象にできないもの・まだ対象にしていないものとその理由は [自動対象の範囲](AUTOMATIC_COVERAGE_2026-10-03.md)。未知のglobal依存では全体を通常描画する。他シーン・キャラクター・音声の依存は該当する区間へ伝える。カスタム読込プラグインでは素材を使うアイテムの区間が対象外となる。

4.56.1.0同梱のシンプル立ち絵は、型・DLLのMVID・配置と `simple-tachie` 契約を確認した場合に対象にする。音量の計算結果ではなく、重なるボイスの有無だけで非表示を決めるため、音量計算の終了を待たない。ホストのpickerで見える表情を選び、上のレイヤーの表情、ボイス側の表情、既定画像、発話がないときの非表示を区間ごとの素材依存にする。使われていない表情の画像の上書きは、その別の区間を止めない。表情用フォルダーは編集画面の設定であり、画像ファイルとして開かない。動画は既存のデコード完成判定を通ってから保存する。グループを含むタイムライン、表情の同一レイヤーの重なり、番号付き画像、未知のパラメーター・版は通常描画へ戻す。動く立ち絵（AnimationTachie）は、4.56.1.0の同梱MVID・場所と `lip-sync-readiness`／`animation-tachie` 契約を確認した場合にPNGの部品を対象にする。ホストが使った音量と公開済みsampleのbit一致、現在のsession／task、取消や途中終了を確認する。未完成や時間切れで0を返した描画は保存せず、親のsceneも未完成にする。画像の番号付き・母音の部品を同期的に列挙し、一度変わった一覧は再起動まで対象外。大文字の母音も含める。画像上書きは既存のHostContentで再起動まで対象外にする。

まばたきはホスト自身の結果を保存し、起動ごとのnonceとitemの同一性を含むSessionキーに限定する。目／口を含む候補部品すべてを依存にするため、使っていない部品の変更でもその立ち絵を対象外にする。付属INIは対象外とし、INIを削除した後に既存sourceへ残る13layerの設定とparts countも参照／保存前に確認する。同じフォルダーの一覧は一度の同期列挙で確認する。一覧は4,096件、記憶する内容はUTF-16で16 MiB、各部品は1,024ファイルまで。採用時のフォルダーに16,384を超えるファイルや大文字小文字だけが違う重複名がある場合も通常描画に戻す。元の一覧を容量確保のために捨てて再登録することはしない。

動画部品・INI・差分合成・group・同一layerの表情競合・入れ子sceneは今回の対応外。停止中の先読みはAnimationTachieを含むroot sceneを見送り、口パクの2つの計算枠を再生へ残す。通常の再生で完成したフレームの2回目の再利用を検査した。外部の立ち絵は引き続き通常描画にする。

PSD立ち絵は、4.56.1.0同梱の立ち絵・合成器・パーサーと `psd-tachie` 契約を確認した場合に対象にする。PSDファイルと、ホストが保持する共有PsdFileSettingsの内容が描画依存になる。通知でキーを記述し直し、通知のない子要素変更も採用前に検出する。ソースに古い正規化済み設定が残っている間、PSDの上書き後、読込／CPU合成失敗、非表示でrootがない状態は通常描画に戻す。まばたきはSessionキー、口パクは2bの完成判定を共有する。停止中の先読みはPSDを含むroot sceneを見送る。sidecar（<PSD名>-ymm.json）の外部上書きはホストの共有設定を自動で再読込しないため、ホストが実際に保持する内容をキーにする。group、同一layerの表情競合、入れ子sceneは対象外。設定の検査上限はHOST_CONTRACTS.mdに記載。
共有設定の記述には専用serializerを使い、アプリ全体のJsonConvert.DefaultSettingsに影響されないようにする。不変のAssembly名とPropertyInfo配列だけを再利用し、loaded assemblies、MVID・DLL位置、設定の実値と子の値は毎回確認する。


4.56.1.0のCommunityで監査した型は自動対象。その他の外部アセンブリは設定で個別に信頼できる（既定は空）。信頼する処理は設定・時刻・報告した素材で描くことが前提で、隠れた履歴・乱数・ファイル等は自動で保証しない。更新MVIDや信頼の変更はキーを変える。OpenFx／VST3は信頼設定でも対象外。[監査境界](HOST_CONTRACTS.md) を参照。

フォントはYMM4と同じくフォント設定から表示名を解決し、未知の名前はArialで描く。ファミリー・太さ・スタイル・幅をキー化し、DirectWriteのシステムコレクションからファミリーのファイルを指紋で検証する。文字装飾・制御タグ、CommunityのShuffleText／ShuffleTextInOut／数値テキストの「フォント」も対象。DirectWriteにないファミリーやフォントにない文字は代替フォントで描かれるため、文字を描くアイテムのキーにはインストール済みフォント全体の識別（ファイルのパス・サイズ・更新時刻）を含める。フォントの追加・削除・更新は10秒以内か次の記述時に検出し、文字を描く区間のキーだけが変わる。ローカルでないフォントファイルのファミリーはその区間だけ通常描画する。数値テキストは数値の書式（カルチャ）をキーに含め、描画するスレッドの書式が記述時と違えばその区間を通常描画する。

オブジェクト同一性を種とする乱数（ランダム移動・RandomMoveEffect・CameraShakeなど）はそのアイテムの生存期間に限定して再利用する。複製では別の乱数になるため、停止中の先読みはそのフレームを複製ではなく実物のシーンを描くsourceで描き、実物のキーで保存する（描画中の編集は破棄）。信頼した外部プラグインが自分で持つ乱数は追跡しないため、複製で描いた値で保存され得る。ランダム表示順のテキスト／字幕は通常描画。MIDI設定・SoundFontはキーに含めていないため、MIDIがある場合の音声を読む区間は通常描画する。

## 選択枠と表示

再生と停止は通常同じ画素を共有し、`ShowOnlyPreviewEffect` があれば分離する。選択枠・操作点は同じキーとrevisionの通常描画から取得した情報を復元する。

選択枠未取得の静止フレームはマウスがプレビュー外なら即時表示し、約0.1秒静止後に通常描画で枠を取得する。マウスが入った場合は直ちに取得する。再生中やマウスがプレビュー上にある場合、未取得の枠が必要なら通常描画する。メッシュ変形や選択枠契約が未確認のホストでも通常描画を維持する。

## 動的な計算と採用判断

任意の不変計算結果を登録・共有するAPI、処理自身が入力状態と時間範囲を報告するprovider、CPU Update+DrawとRAM復元の費用を区別した保存判断を追加した。無損失圧縮・費用の限界・callbackのスレッド条件・未対応箇所は [動的キャッシュAPI](DYNAMIC_CACHE_API.md) を参照。合成済みフレームの描画SingleFlight、効果途中の自動保存、再生scheduler、MFRは未実装。

### 停止中の描画器の本数（項目8）

設定「停止中の描画器」はAuto／1／2／4本を選べる（保存設定の3本も保持する）。最大4本の専用STAスレッドを必要時に作り、各作業者が自分の複製・tracker・描画デバイスを持つ。デバイスの作成・使用・破棄は同じスレッドで行う。作業のない描画器は2秒で破棄し、作業スレッドは待機する。

Autoは論理コアの半分を上限とし、GPU予算から現在の使用量と余裕（1 GiBまたは予算の1/5の大きい方）を引いた空きに収める。描画器を作る前と描いた後のプロセスGPU使用量の増加を観測し、増加の2倍と512 MiBの大きい方を1本の予約として使う。並行したプロセス内の割当も含むため、厳密な単一デバイスのVRAM計測ではなく、保守的な見積もりである。正の増加を観測できるまでは1本、取得失敗・WARPも1本。アダプターの変更時は測定を捨て、再び1本から始める。手動は1～4本で、WARPの並列検査にも使える。

通常フレームは先読み順の番号を本数で割った余りで分配する。実物のオブジェクトで描くSessionフレーム（ランダム移動など）は作業者0だけが受け持ち、ほかの作業者は描画直前にもライブ描画を拒否する。完了順が前後しても、再開位置は完成した連続区間までしか進めない。

再生・編集・タイムライン移動・入力・無効化では先読みを取り消し、表示上の本数は1本へ戻る。AutoでGPUの余裕が減った場合も取り消す。YMM4の進行中のUpdateを強制終了せず、更新から戻った全作業者が保存を見送り、各デバイスを所有スレッドで返す。保存の世代券は描画前に取り、途中の消去では複製・ライブどちらの描画も古い世代へ保存しない。

詳細ログの`idle-frame`には作業者番号（`Component`）、`workers`、`measured-worker-reserve`、結果（`Outcome`）を記録する。時間はUpdate・保存・待ちを含むCPUの壁時計であり、GPU単体の実行時間ではない。利用者のPCでは同じ重い場面を停止した状態で1本と2本を比べ、保存帯が埋まる時間・記録件数・GPUの使用量と予算、操作／再生開始後の取消を確認する。

記述のResourcesには、画面に出ていないランダム項目のobject identityも入る。複製との記述の比較では、Root の Resources 配列の identity://、animation-blink-session://、psd-blink-session:// の値だけを同じ印に置き換える（接頭辞と件数は保持）。数とそれ以外のJSON文字列・数値の表記・入れ子のResourcesはそのまま保持する。各フレームのキーは依然として完全一致が必要で、active Sessionはidentityに依存するライブ描画のまま。この扱いにより、ランダム項目のない前半を別作業者の複製で描き、後半を作業者0で描ける。


### 編集後の差分記述を有効にしない理由（項目5、PR #11）

変更通知と子の値の確認を使う差分JSONの試作は、1,000回の編集で全体の記述と完全一致し、1件編集で999件を再利用できた。しかし1,000アイテムの編集後の記述は111〜420 msで、目標の10 ms台には届かず、正規化した値も一部で悪化した。初回の検査・購読・メモリの負担に見合う改善を確認できないため、製品は全体の記述と依存索引の再計算を維持する。試作と比較はHostCacheProbeのテストだけに残している。250 msの落ち着き待ちや未知の型の扱いは変えない。[結果](SPEEDUP_RESULTS_2026-10.md) に同一CI jobの値と再現方法を記録した。

PSDをキャッシュ有効化前に読み込んでいた場合も、parserが保持するreadonly bytesのSHA-256（parsed file ごとに一度、背景 task・buffer コピーなし）と capture の lease 指紋を比較する。完了前・失敗時は通常描画で保存・再利用しない。不一致ならHostContentを再起動まで対象外にし、古い画素を新しいファイルのキーへ保存しない。元のstreamや配列の所有権は変更しない。

停止中の先読みは native animation / PSD 立ち絵の表示区間だけを見送り、表示区間外は複製から先読みする。計算枠の非同期予約を安全に渡す host API がないため、空き数を見ただけで表示区間内の先読みを許可しない。大きな素材の確認費用の改善と今後の課題は [Claude レビュー対応（2026-10-05）](SPEEDUP_REVIEW_RESPONSE_2026-10-05.md)。

# 描画キャッシュの仕様

2026-10-02の実装を含む仕様。入口は [README](../README.md)、開発課題は [AE_CACHE_DEVELOPMENT.md](AE_CACHE_DEVELOPMENT.md)。

## 保存と供給

標準プレビューの再生・一時停止・シークと、動画出力で完成した合成済みフレームを保存する。デコードが要求時刻まで完了したと確認できない場合は保存しない。判定とホスト互換性は [HOST_CONTRACTS.md](HOST_CONTRACTS.md)。

RAM／ディスクから復元したプレビュー画像は、予算と利用履歴に応じてGPU上に保持する。保持した画像の再利用ではCopyFromMemoryを省ける。初回レンダーのCPU readbackは残り、ホストの可変effect graphをそのまま保持することはしない。 ライブプレビューのreadbackは実際のD2D描画先と同じD3D11 deviceのstaging textureへコピーし、`Map(Read, DoNotWait)`で完了を確認する。GPU処理中は待たず、次の描画タスク更新で再試行する。各sourceで保留は3枚までとし、3枚ともGPU処理中のときだけ新しい保存を省略する。保存するフレームは一度だけ描き、保存用に描いた画素をそのまま表示する。未完成画像は保存しない。消去・編集・入力変更後の古いコピーも採用しない。動画出力のフレームも同じ方式（各sourceで保留3枚まで、プールなし）で保存し、GPUの完了を毎フレーム待たない。3枚とも保留中なら最も古い1枚（3フレーム前）の完了を待つため、出力した全フレームを保存する。出力の最後に残った保留分は、出力用のsourceを破棄するときに完了させて保存する。明示的なcaptureとidle先読みは同期完了を使う。[GPU保持の設計](GPU_FRAME_RETENTION.md) を参照。

ディスクI/O、初期化、索引、整合性検査は専用workerで行う。読込は書込より優先し、実測読込費用に応じて再生位置の0.5〜2秒先まで先読みする（最大120フレーム、窓は半RAM予算でも制限）。一時停止時は描画タスク上で最大50 msの読込を待ち、間に合わなければ通常描画する。起動直後に索引を読み込んでいる間は、索引にまだ無いフレームのために待たない。再起動後のディスクLRUは、各レコードの最終書込時刻（ディスクから読んだときにも更新する）の順に組み立て、容量を超える分は最も古く使われたものから消す。消去は保存世代を永続化し、削除できなかった旧ファイルが次回起動で復活することを防ぐ。永続化失敗はツールに表示する。

## メモリと容量

| 対象 | 現行の上限・方式 |
| --- | --- |
| RAM設定上限 | 既定2048 MiB、64〜16384 MiB。自動調整または手動固定 |
| RAMストア | LRU、最大1024 entry。借用中の不変画素は退避後も有効 |
| ディスク | 4 GiB、Brotliによる無損失圧縮／raw fallback |
| 1フレーム | 128 MiB（保存ヘッダーを含む） |
| ディスクキュー | 128件、待機中の書込画素128 MiB。満杯なら追加保存を省略 |
| GPU保持 | 描画に使うGPUのVRAMに応じた自動配分（初期128 MiB、搭載VRAMの1/4まで、設定上限の既定2048 MiB）か、上限での手動固定。entry数は予算に比例して64〜1024。画像総予約は保持＋256 MiB |

GPU予算は画素payloadの予約であり、ドライバーの実VRAM全量ではない。

VRAMの自動配分は、描画スレッド外で1秒ごとに、描画に使うアダプターの値を `IDXGIAdapter3::QueryVideoMemoryInfo`（ローカル）で採取する。採取するのは、このプロセスへのOSの予算と現在の使用量。

- 保持の目標は「予算 −（YMM4の保持以外の使用量）− 余裕」とする。余裕は max(1 GiB, 予算の1/5)。
- 目標は、搭載VRAMの1/4（128 MiB〜4 GiB）と設定上限で抑える。
- 使用量が「予算 − 余裕の半分」を超えたら、直ちに半分以下にする。
- 健康なサンプルが3回続くごとに128 MiBずつ増やす。
- ソフトウェア描画（WARP）や取得に失敗したときは、値を保ち、増やさない。
- 予算を下げても、保持フレームの解放は次の描画（Update）で描画スレッドが行う。

自動RAM配分は描画スレッド外で1秒ごとにOS空き物理RAM・process private bytes・managed heap・GC上限を採取する。設定上限と物理RAMの1/4以下を予算とし、OSへ最大(1 GiB, 物理RAMの1/8)を残す。プロセス全体は物理RAMの1/2を目安にし、書込キューと最大1フレームの余裕も確保する。圧力時は直ちに縮小し、健康なサンプルが3回続いた回復時には128 MiBずつ増やす。取得失敗では増やさない。

RAM縮小でも有効なディスクレコードは残す。借用配列、書込キュー、YMM4本体、デコーダーはRAMストアの使用量とは別で、縮小直後にプロセス使用量が下がるとは限らない。GCを強制実行しない。

1080p BGRAでは256 MiBが約32枚、2 GiBが約258枚の画素量に相当する。全区間を巡回できても、全フレームを同時に保持できるとは限らない。

## 停止中の先読みと帯

停止中は最後の操作から既定8秒後に30フレームずつ設定範囲（既定はタイムライン全体）を巡回する。巡回するタイムラインはツール「描画キャッシュ」から受け取るため、ツールを開いている間だけ動く。開始フレームと終了フレームを設定でき、終了は含まない。終了0は末尾。現在位置から末尾→先頭、現在位置の前後、先頭からの順序を選べる。停止中の先読みだけを無効にもできる。

保存済み・恒久的に通常描画が必要なフレームは飛ばす。入力・編集・シーク・再生・ビュー変更・消去で中断し、次の有効な状態で再開する。未完成デコード等で保存できなかったフレームを無期限に再試行するものではない。

緑はRAM、青はディスクの保存状態。ツールはタイムライン全体、対応ホストのルーラーは表示範囲に帯を出す。帯は現在のviewportのキーに対応する表示であり、実際の表示FPSや全フレーム検査の証明ではない。帯は250 msごとに確認するが、保存内容・フレームのキー・表示範囲が変わらない間は照会を省く（最長2秒ごとには照会し直す）。

## キーと無効化

キーは正確な時刻ticks（100 ns）、fps、usage、描画環境、viewport、モデル、素材の指紋から作る。永続schemaは `pixels-v7`。GPU・ドライバー・プラグインのビルドが変われば以前の画素は再利用しない。

通常は全体設定とそのフレームに重なるアイテムを依存に含める。トランジションは直前フレームのアイテムも追う。シーンアイテムと音声波形図形の区間はプロジェクト全体に依存する。描画に使う補間、読込方式、音声アップサンプリング、拡張子設定、フォント設定、テキスト／字幕の「*」置換もキーに含める。レイヤーの名前と色は描画しないためキーに含めない。ルートのタイムラインのレイヤー音量は、音声を読む区間（シーンアイテム・音声波形）のキーだけに含める。非表示のレイヤーは全区間のキーに含める。

編集後250 ms以内は通常描画し、変更が落ち着いてから記述し直す。YMM4の設定のうち描画に使わない項目（タイムラインの拡大率、プレビューの音量、画面の配置など）の変更では記述し直さない。無関係な区間の内容キーを保ち、Undo後も一致した状態を再利用する。記述処理はまだwhole-project JSONを起点とし、モデル上限は16×1024×1024文字。完全な差分記述は未実装。

素材の背景検証は最大4096ファイル。要求フレームで使う素材から検証し、採用時にもファイルleaseとキーの指紋を照合する。確認できないファイル（リンクやクラウドの代替ファイルを含む場所、NTFS以外やネットワークのドライブ、4 GiB超、見つからない、読めない）は依存区間だけ通常描画にし、停止中の先読みはその区間を飛ばす。そのファイルだけを30秒ごと、または有無・サイズ・更新時刻が変わったときに確認し直す（プロジェクト全体は確認し直さない）。

YMM4起動中に同名素材を上書きすると、ホストは読み込み済みの古い内容を保持し得る。変更を検出したファイルを使う区間は、内容を戻しても再起動まで通常描画する。キャッシュ無効中で、まだ検証していない間の上書きは検出できない。

## 外部処理・フォント・乱数

未監査のエフェクト・図形・アイテム・トランジション・ブラシは依存するアイテムの区間だけ通常描画する。未知のglobal依存では全体を通常描画する。他シーン・キャラクター・音声の依存は該当する区間へ伝える。立ち絵は非同期口パクのため通常描画。カスタム読込プラグインでは素材を使うアイテムの区間が対象外となる。

4.56.1.0のCommunityで監査した型は自動対象。その他の外部アセンブリは設定で個別に信頼できる（既定は空）。信頼する処理は設定・時刻・報告した素材で描くことが前提で、隠れた履歴・乱数・ファイル等は自動で保証しない。更新MVIDや信頼の変更はキーを変える。OpenFx／VST3は信頼設定でも対象外。[監査境界](HOST_CONTRACTS.md) を参照。

フォントはYMM4の一覧から表示名を解決し、未知の名前はArialへ落とす。ファミリー・太さ・スタイル・幅をキー化し、DirectWriteのシステムコレクションからファミリーのファイルを検証する。解決できないファミリーはその区間だけ通常描画する。文字装飾・制御タグのフォントも対象。DirectWriteの代替フォントは追跡せず、一覧再読込なしのface追加にも限界がある。

オブジェクト同一性を種とする乱数はそのアイテムの生存期間に限定して再利用し、複製するidle先読みでは使わない。ランダム表示順のテキスト／字幕は通常描画。MIDI設定・SoundFontはキーに含めていないため、MIDIがある場合の音声を読む区間は通常描画する。

## 選択枠と表示

再生と停止は通常同じ画素を共有し、`ShowOnlyPreviewEffect` があれば分離する。選択枠・操作点は同じキーとrevisionの通常描画から取得した情報を復元する。

選択枠未取得の静止フレームはマウスがプレビュー外なら即時表示し、約0.1秒静止後に通常描画で枠を取得する。マウスが入った場合は直ちに取得する。再生中やマウスがプレビュー上にある場合、未取得の枠が必要なら通常描画する。メッシュ変形や選択枠契約が未確認のホストでも通常描画を維持する。

## 動的な計算と採用判断

任意の不変計算結果を登録・共有するAPI、処理自身が入力状態と時間範囲を報告するprovider、CPU Update+DrawとRAM復元の費用を区別した保存判断を追加した。無損失圧縮・費用の限界・callbackのスレッド条件・未対応箇所は [動的キャッシュAPI](DYNAMIC_CACHE_API.md) を参照。合成済みフレームの描画SingleFlight、効果途中の自動保存、再生scheduler、MFRは未実装。
